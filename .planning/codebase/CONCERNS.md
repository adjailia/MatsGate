# Codebase Concerns

**Analysis Date:** 2026-08-19

## Tech Debt

**Massive client-side data load:**
- Issue: `data/products.json` is 11.3MB (7430 products) and is fetched entirely into browser memory on page load
- Files: `data/products.json`, `script.js:40-46` (`loadProducts`)
- Impact: Slow initial load, high memory consumption on mobile devices, poor Core Web Vitals. The entire JSON is parsed and stored in the `allProducts` global array, then filtered in-memory on every filter change
- Fix approach: Implement pagination on the data side (split into pages), add server-side filtering via Cloudflare Workers, or implement lazy/incremental loading

**Monolithic single-file architecture:**
- Issue: All application logic (497 lines) lives in a single `script.js` file with no modules, no bundling, and global mutable state
- Files: `script.js` (all lines), `index.html:122`
- Impact: Difficult to maintain, test, or scale. All state (`allProducts`, `selectedProducts`, `wishlist`, `currentPage`, `filteredProducts`, `saleFilterActive`) is in global scope
- Fix approach: Refactor into ES modules (e.g., `modules/products.js`, `modules/filters.js`, `modules/ui.js`, `modules/compare.js`). Use a bundler like Vite for tree-shaking and minification

**No build tooling or minification:**
- Issue: No CSS/JS minification, no asset optimization, no image optimization pipeline. Raw source files are served directly to production
- Files: `script.js`, `style.css`, `index.html`
- Impact: Unnecessarily large payloads. `style.css` is 910 lines served raw, no CSS purging of unused rules
- Fix approach: Add Vite or similar build tool with CSS/JS minification, asset hashing, and image optimization

**Manual CSV-to-JSON pipeline:**
- Issue: Product data must be regenerated by running `node generate.js` manually after updating `data/products.csv`. The CSV parser in `generate.js` is hand-written with basic quote handling
- Files: `generate.js:32-123` (`parseCSV` function), `run.sh`
- Impact: Error-prone. The CSV parser does not handle escaped quotes (`""`) within quoted fields, newlines inside quoted fields, or edge cases in the Awin CSV feed. Silent data corruption possible
- Fix approach: Use a battle-tested CSV library (e.g., `papaparse`) instead of the hand-rolled parser at `generate.js:32`

**Stale error log committed to repo:**
- Issue: The `errer/` directory contains a Cloudflare build failure log that should not be in version control
- Files: `errer/matsgate.production.e10003b1-c34b-4405-b130-7b5f60c7d498.build.log`
- Impact: Clutters repo. The directory name itself (`errer`) suggests a typo of "errors" and was added to `.gitignore` AFTER the file was committed
- Fix approach: Remove the file from git tracking (`git rm --cached`), ensure `.gitignore` covers it (already does)

**Hardcoded Font Awesome CDN with beta version:**
- Issue: Font Awesome 6.0.0-beta3 is loaded from cdnjs. This is a pre-release version that may have bugs or missing icons
- Files: `index.html:16`
- Impact: Beta versions may have breaking changes, missing features, or security patches not yet applied
- Fix approach: Upgrade to a stable Font Awesome release (e.g., 6.5.x or 6.6.x) and consider self-hosting for performance and reliability

**Duplicate product entries in data:**
- Issue: Multiple products with the same name and description but different IDs exist in the dataset (e.g., Chloé "Signature Le Parfum" appears 4 times with IDs 146622-146625, all sharing the same image and affiliate link but different prices/sizes)
- Files: `data/products.json`, `data/products.csv`
- Impact: Users see near-identical products in the grid, confusing the comparison experience. No deduplication logic exists
- Fix approach: Add deduplication to `generate.js` or implement grouping in the UI (e.g., show as "available in 3 sizes" with expandable options)

## Known Bugs

**Broken Cloudflare Pages deployment:**
- Symptoms: Build fails with error: `Cannot use assets with a binding in an assets-only Worker`
- Files: `wrangler.json:1-7`
- Trigger: Running `npx wrangler deploy` or any Cloudflare Pages build. The `wrangler.json` specifies `"assets": { "directory": "." }` but also implicitly creates an assets-only Worker, which conflicts
- Workaround: Fix `wrangler.json` by either adding a `main` field pointing to a worker script, or using Cloudflare Pages' simpler static-asset configuration instead of Workers assets binding

**XSS via product data in innerHTML:**
- Symptoms: Product titles, descriptions, brands, and other fields are injected directly into HTML via template literals and `innerHTML` without escaping
- Files: `script.js:196-226` (product card rendering), `script.js:369-412` (comparison table)
- Trigger: Any product with HTML/script content in its `title`, `description`, `brand`, or `category` field would execute in the browser. The CSV feed from Awin could contain adversarial data, and currently 40+ product descriptions contain raw HTML tags (e.g., `<i>`, `<a>`)
- Workaround: Implement an `escapeHtml()` utility and apply it to all user-facing data before innerHTML insertion. Alternatively, use `textContent` and DOM APIs for dynamic content

**Price display inconsistency for "no sale" products:**
- Symptoms: When `sale_price` equals `price` (e.g., product ID 119313: `"price": "25.90 EUR", "sale_price": "25.90 EUR"`), the UI shows both a strikethrough old price and a "PROMO" badge even though there is no actual discount
- Files: `script.js:141` (`matchSale` logic), `script.js:187-194` (sale badge/price rendering)
- Trigger: Any product where the feed provider sets `sale_price` equal to `price`
- Workaround: Add a check in `getFilteredProducts` and `renderProducts` that treats `sale_price === price` as no sale

**Missing `og:image` meta tag:**
- Symptoms: Social media sharing shows no preview image
- Files: `index.html:11-13`
- Trigger: Sharing the site URL on social platforms (Facebook, Twitter, LinkedIn)
- Workaround: Add `<meta property="og:image" content="https://metsgate.com/images/LOGO_150.png">` to the `<head>`

## Security Considerations

**Cross-Site Scripting (XSS) — HIGH RISK:**
- Risk: All product data is rendered via `innerHTML` without sanitization. The Awin affiliate feed data flows directly from CSV → JSON → DOM. If the feed contains malicious HTML/JS, it executes in every visitor's browser
- Files: `script.js:196-226` (product cards), `script.js:329-413` (comparison modal), `script.js:203` (image `onerror` handler)
- Current mitigation: None. No Content Security Policy (CSP) headers, no input sanitization, no DOMPurify or equivalent
- Recommendations: (1) Add an `escapeHtml()` function and wrap all data interpolation in innerHTML. (2) Add CSP headers via Cloudflare to restrict inline scripts. (3) Consider using DOM APIs (`createElement`, `textContent`) instead of innerHTML for dynamic content

**No Content Security Policy:**
- Risk: Without CSP, any injected script runs unrestricted. The `<script src="script.js">` and inline `onerror` handler on `<img>` tags are vectors
- Files: `index.html` (no CSP meta or headers configured), `wrangler.json` (no headers config)
- Current mitigation: None
- Recommendations: Add `Content-Security-Policy` meta tag or configure via Cloudflare headers. At minimum: `default-src 'self'; script-src 'self'; img-src 'self' https://perfumeriacomas.com https://via.placeholder.com`

**Affiliate link exposure in client-side code:**
- Risk: All Awin affiliate deep links (containing `awinmid=105475&awinaffid=3039511`) are exposed in the client-side JSON. These could be scraped or used to generate fraudulent clicks
- Files: `data/products.json` (every product's `affiliate_link` field)
- Current mitigation: `rel="nofollow sponsored"` on links (line `script.js:220`)
- Recommendations: Consider proxying affiliate clicks through a server-side redirect to hide the publisher ID, or accept the exposure as standard for static affiliate sites

**localStorage used for state persistence without validation:**
- Risk: `selectedProductIds` and `wishlist` are read from `localStorage` and added to a `Set` of product IDs without validating that the IDs exist in the product catalog
- Files: `script.js:48-52`
- Current mitigation: None — invalid IDs silently remain in the Set, potentially causing the compare feature to show no products
- Recommendations: Validate loaded IDs against `allProducts` after loading. Remove any IDs not found in the catalog

## Performance Bottlenecks

**Full product list re-render on every filter change:**
- Problem: Every filter interaction (search, brand, category, price range, sale toggle) triggers a full re-render of the current page via `innerHTML` replacement, destroying and recreating all DOM nodes and re-attaching all event listeners
- Files: `script.js:147-153` (`applyFiltersAndRender`), `script.js:177-238` (`renderProducts`)
- Cause: No virtual DOM, no diffing, no event delegation. Each `renderProducts` call does `productGrid.innerHTML = html` (line 228) then re-queries all checkboxes and buttons to attach listeners (lines 231-237)
- Improvement path: Use event delegation on `productGrid` instead of per-element listeners. Use `DocumentFragment` for batch DOM updates. Consider a lightweight reactive library

**Search runs on every keystroke without debouncing:**
- Problem: The search input only triggers on Enter key or button click (line 436-439), but the price range sliders fire `applyFiltersAndRender` on every `input` event (lines 443-457) without debounce, causing expensive full re-renders during slider drag
- Files: `script.js:443-457`
- Cause: No debounce/throttle utility applied to price slider input events
- Improvement path: Add a debounce (150-300ms) to the price range input handlers. Consider using `requestAnimationFrame` for visual updates during drag

**11.3MB JSON fetched as a single HTTP request:**
- Problem: `data/products.json` is fetched via a single `fetch()` call. On slow connections, this blocks the entire app during load
- Files: `script.js:43`, `data/products.json` (11.3MB)
- Cause: No chunking, no streaming, no compression optimization
- Improvement path: Enable Brotli/gzip compression on Cloudflare. Consider splitting the JSON into chunks or implementing server-side pagination via a Cloudflare Worker

**Images loaded from external domain without sizing optimization:**
- Problem: All product images are loaded from `perfumeriacomas.com` CDN. Images use `loading="lazy"` (good) but there are no width/height attributes specified, causing layout shifts
- Files: `script.js:203-206` (product card images)
- Cause: No `width`/`height` on `<img>` tags. The `onerror` fallback also triggers a network request to `via.placeholder.com`
- Improvement path: Add explicit `width` and `height` attributes to prevent CLS. Consider implementing a proper `<picture>` element with responsive sizing

## Fragile Areas

**CSV Parser (`generate.js:32-123`):**
- Files: `generate.js:32-123`
- Why fragile: Hand-rolled CSV parser handles basic quoted fields but does not handle: escaped quotes within quoted fields (`""` → `"`), newlines within quoted fields, or fields containing commas inside quotes without surrounding quotes. The Awin product feed CSV (7430 lines) contains HTML entities (`&amp;`, `&lt;`, `&apos;`) that are only partially decoded (line 92-93)
- Safe modification: Replace with `papaparse` library. Until then, always validate output counts match input line counts after regeneration
- Test coverage: None

**Global mutable state:**
- Files: `script.js:3-9` (global variables: `allProducts`, `selectedProducts`, `wishlist`, `currentPage`, `productsPerPage`, `filteredProducts`, `saleFilterActive`)
- Why fragile: Any function can mutate any global. No encapsulation. Race conditions possible if `loadProducts` async fetch completes while user interacts with filters
- Safe modification: Wrap in an IIFE or module pattern. Use a single state object with update functions
- Test coverage: None

**Price parsing from string format:**
- Files: `script.js:116-121` (`getNumericPrice`)
- Why fragile: Parses prices like "16.95 EUR" using regex. Handles comma-as-decimal (`replace(',', '.')`) but does not handle: prices with thousands separators ("1,234.50 EUR"), non-EUR currencies, or empty/malformed price strings gracefully (returns 0 silently)
- Safe modification: Add validation and logging for price parsing failures. Consider normalizing prices to numeric cents in `generate.js`
- Test coverage: None

**URL-based comparison sharing:**
- Files: `script.js:284-311` (`shareComparison`, `loadCompareFromURL`)
- Why fragile: Product IDs from the URL query string are directly added to the `selectedProducts` Set without validation. If the product catalog changes (products removed), stale IDs persist in shared URLs and silently fail in the comparison view. No maximum limit on number of products shareable via URL
- Safe modification: Validate URL IDs against `allProducts` before adding. Cap at 10 products maximum
- Test coverage: None

## Scaling Limits

**Client-side product catalog:**
- Current capacity: ~7430 products (11.3MB JSON). Performance degrades noticeably on mobile devices
- Limit: Browser memory and parse time. Chrome can handle ~50MB JSON but mobile Safari may struggle at 20-30MB. Current growth rate from Awin feed could reach this within a year
- Scaling path: Move filtering/sorting to a Cloudflare Worker. Implement pagination at the API level. Consider a lightweight database (Cloudflare D1 or KV)

**localStorage capacity:**
- Current capacity: 5-10MB depending on browser
- Limit: Product IDs stored as JSON arrays in `selectedProductIds` and `wishlist`. At current 7430 products, maximum wishlist size would be ~80KB — well within limits
- Scaling path: Not an immediate concern, but consider migrating to IndexedDB if the app needs to store richer user data (search history, price alerts)

## Dependencies at Risk

**Font Awesome (via CDN):**
- Risk: Version 6.0.0-beta3 is a pre-release. The cdnjs CDN could go down, and the beta may have unpinned sub-dependencies
- Impact: All icons in the UI (search, filter, heart, cart, share, pagination) would show as broken squares
- Migration plan: Upgrade to stable Font Awesome 6.x, self-host the CSS and font files in `images/` or a dedicated `assets/` directory, add a fallback `font-family` stack

**via.placeholder.com (image fallback):**
- Risk: External service used as fallback for broken product images (`script.js:203`, `script.js:206`). The service has no SLA and may be blocked by corporate firewalls or ad blockers
- Impact: Broken product images show nothing instead of a placeholder
- Migration plan: Host a local placeholder image (e.g., `images/placeholder.png`) and use it as the fallback `src`

**Awin affiliate network (single provider):**
- Risk: All products come from a single Awin advertiser (`advertiser_id: 105475`, Perfumeria Comas). If the affiliate relationship ends or the feed format changes, the entire product catalog goes stale
- Impact: Complete loss of product data and revenue
- Migration plan: Monitor feed freshness. Add a timestamp check in `generate.js` to flag stale data. Consider adding secondary affiliate feeds

## Missing Critical Features

**No analytics or error tracking:**
- Problem: No way to monitor site usage, errors, or performance in production
- Blocks: Cannot measure SEO impact, user engagement, or diagnose production issues

**No sitemap.xml or robots.txt:**
- Problem: The site has SEO meta tags but no sitemap or robots.txt file, limiting search engine crawl efficiency
- Blocks: Google indexing of individual product pages (if they existed) or the main page

**No service worker or offline support:**
- Problem: The site requires a network connection to load `products.json`. No caching strategy for offline or flaky network scenarios
- Blocks: Progressive Web App capabilities, mobile reliability

**No accessibility (a11y) considerations:**
- Problem: No ARIA labels on interactive elements, no keyboard navigation for the comparison modal, no focus management, no skip-to-content link. The dark mode toggle has no `aria-label` or `role` attribute
- Blocks: Screen reader usability, keyboard-only navigation, WCAG compliance

## Test Coverage Gaps

**Entire application is untested:**
- What's not tested: Every function in `script.js` (497 lines) and `generate.js` (134 lines) has zero test coverage. No unit tests, integration tests, or end-to-end tests exist
- Files: `script.js`, `generate.js`, `index.html`, `style.css`
- Risk: Any code change could break filtering, comparison, price parsing, or data loading without detection. The CSV parser is particularly fragile and needs validation tests against edge cases
- Priority: High — at minimum, add tests for `getNumericPrice()`, `getFilteredProducts()`, `parseCSV()`, and the comparison URL round-trip logic

**No CI/CD pipeline:**
- What's not tested: No automated checks run before deployment. The Cloudflare build is the only "test" and it currently fails
- Files: No `.github/workflows/`, no CI config files
- Risk: Bugs ship directly to production
- Priority: High — add a basic CI pipeline with linting (ESLint), and ideally Playwright or Cypress for E2E smoke tests
